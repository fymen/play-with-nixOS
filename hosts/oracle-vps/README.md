# Oracle VPS

`oracle-vps` targets the Oracle Cloud Seoul `VM.Standard.E2.1.Micro` instance
at `130.162.149.210`: x86-64, 1 GB RAM and a 50 GB boot volume.
The separate `vps` configuration describes another machine.

The hardware module preserves the original Ubuntu root, `/boot` and EFI
partitions, using UUIDs inspected on this instance. Recheck these UUIDs after
recreating the instance. GRUB uses `/boot/efi` and keeps three generations.
SSH uses public keys for `root` and `oscar`; password login is disabled.
Zram is enabled and local Nix builds are limited to one job.

## Installation

The installation uses the reviewed `elitak/nixos-infect` script, followed by
deployment of this flake. The base installation uses `nixos-26.05`.
The reviewed script has SHA-256
`4354bd68773b41da65c0e815202c43c8549713b3ed3ff6381c71fbc0b0a840ab`.
The temporary installation module adds the separate ext4 `/boot` partition,
serial console, one build job and `boot.initrd.systemd.enable = false`.
The scripted initrd is needed only for nixos-infect's initial lustration.
The repository configuration uses the standard systemd initrd afterwards.
No OCI boot-volume backup is requested. The old Ubuntu root is moved to
`/old-root` by the installer; it is not automatically deleted.

On 2026-11-24, both the base installation and deployment were reboot-tested.
The deployed locked system is `26.11.20260616.567a49d` with kernel `6.18.35`.
Root and oscar key login, oscar sudo, DHCP, Home Manager and outbound HTTPS
were verified; no failed systemd units remained. Xray was subsequently provisioned
and tested through the public endpoint as described below.

## Build and deploy

Build on a larger x86-64 machine using the existing lock file:

```sh
nix eval --no-update-lock-file .#nixosConfigurations.oracle-vps.config.system.build.toplevel.drvPath
nix build --no-update-lock-file --out-link result-oracle-vps .#nixosConfigurations.oracle-vps.config.system.build.toplevel
```

Deploy the built closure, then set the system profile and activate it:

```sh
nix copy --substitute-on-destination --to ssh://root@130.162.149.210 "$(readlink -f result-oracle-vps)"
ssh root@130.162.149.210 "nix-env --profile /nix/var/nix/profiles/system --set $(readlink -f result-oracle-vps)"
ssh root@130.162.149.210 /nix/var/nix/profiles/system/bin/switch-to-configuration switch
```

A Makefile wrapper builds locally and deploys to `root@130.162.149.210`:

```sh
make test_deploy HOST=oracle-vps  # Temporary activation; does not change boot default
make deploy HOST=oracle-vps       # Permanent switch
```

Both commands use the existing lock file. Override `DEPLOY_HOST` or `BUILD_HOST`
when needed. Leave `BUILD_HOST` empty (the default) or set it to `localhost`
for a local build without SSH; set `BUILD_HOST=user@builder` for a remote build.
Without `HOST`, these deployment targets still select `vps`.
SSH options can be passed through `NIX_SSHOPTS`; if the local SSH configuration
has permission errors, use `NIX_SSHOPTS='-F /dev/null'` to bypass it.
A reboot is needed to verify kernel, initrd and bootloader changes.
The remote `/etc/nixos` files are the temporary nixos-infect installation
configuration. Subsequent deployments must use this flake's `oracle-vps` output;
a bare `nixos-rebuild switch` on the VPS would select the bootstrap configuration.

## Xray

`configuration.nix` declares the protocol, Vision flow, listener, REALITY target,
logging and routing. Credentials are encrypted in `secrets/xray.age`, with
recipients declared in `secrets/secrets.nix`. Agenix decrypts them at activation;
systemd passes them to Xray using `LoadCredential`. The service merges credentials
with the public Nix template into `/run/xray/config.json` and validates it before
starting. Plaintext credentials never enter the repository or Nix store.
The NixOS firewall permits TCP 22 and 443; OCI ingress must also permit them.

On 2026-11-24, Xray 26.3.27 was configured for VLESS + REALITY with
`xtls-rprx-vision`, listening on `130.162.149.210:443`. The REALITY target is
`www.bing.com:443`, with server name `www.bing.com` and client fingerprint
`chrome`. Microsoft was rejected during connection testing because its TLS
handshake did not work with this REALITY implementation; Bing passed the test.
No domain registration or local TLS certificate is needed for this setup.

Runtime files on the VPS:

- `/run/agenix/oracle-xray`: root-only decrypted credentials, mode `0400`.
- `/run/xray/config.json`: generated configuration, mode `0600`, owned by the
  service's dynamic user inside its private runtime directory.
- `/root/xray/v2rayn.txt`: private VLESS import URI for v2rayN, root-only `0600`.
- `/root/xray/client-test.json`: matching test client, root-only `0600`.

The two client files are deployment artifacts, not generated by Nix. Keep all
plaintext files out of Git and the Nix store. The server configuration blocks
proxy requests to private, loopback, link-local (including OCI metadata) and
multicast addresses. Logs use warning level; REALITY debug output is disabled.
The service is enabled at boot and reads credentials afresh when restarted.

In v2rayN, copy the entire URI from `/root/xray/v2rayn.txt`, import servers from
the clipboard, and select `OCI-Seoul-REALITY` as the active server. Use the Xray
core and enable the system proxy as needed. Treat the URI as an access credential.
After changing the UUID, REALITY keys, short ID, port or server name, update the
client configuration and import URI together.

Evaluate and build Nix changes using the commands above, then deploy the new
system closure. Both template and encrypted credential changes trigger a service
restart. The service validates the merged JSON on every start. Inspect it with:

```sh
sudo systemctl status xray --no-pager
sudo journalctl -u xray --no-pager -n 30
```

To edit credentials, run `agenix -e xray.age` from `hosts/oracle-vps/secrets/`
using the private key matching the oscar recipient. The JSON contains `clients`
(a list of objects with an `id` UUID), `privateKey` and `shortIds`. Vision flow is
enforced by Nix. Update the client artifacts after rotating credentials.

When recreating the instance, preserve SSH host identity or decrypt with the
oscar identity and re-encrypt for the replacement host's public key. Update
`secrets/secrets.nix` and run `agenix -r` with an authorized identity before
deployment. Merely changing the recipient list does not re-encrypt the file.
The old `/var/lib/xray/config.json` is no longer used by the service.

A local Xray client using the same parameters was tested directly against public
TCP 443 (without an SSH tunnel). HTTPS requests to `api.ipify.org` and
`cache.nixos.org/nix-cache-info` succeeded; the observed exit IP was
`130.162.149.210`. The v2rayN graphical client itself was not exercised.
